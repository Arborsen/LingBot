# 训练与评测设计

项目目标是在有限GPU资源下，对官方LingBot-VLA 2.0做50任务联合微调，并使续训状态、任务覆盖、仿真条件与成功率统计可以追溯。模型架构、基础权重、Distributed Muon实现与RoboTwin平台来自上游；本项目的工程实现范围见[贡献清单](../contributions/README.md)。

## 数据与任务采样

训练使用官方clean演示，每任务50条，共2500条episode。当前导出的数据共有548893帧。randomized场景只用于测试。

LeRobot中的`task_index`表示语言指令索引，同一个机器人任务可能有多种指令，不能直接把它当成50个机器人任务的分类标签。[task_mapping.py](../tools/continuation_15000/task_mapping.py)检查连续episode分组、官方指令模板、帧区间连续性、任务唯一性，以及12条通用/缺省措辞的精确复核例外。

[TaskSampler](../tools/continuation_15000/stage_data.py)先选择任务，再在任务内均匀抽帧。10个弱任务使用1.5倍权重，其余任务权重1，总权重55：

- 每个弱任务概率为$1.5/55\approx2.73\%$。
- 其他每个任务概率为$1/55\approx1.82\%$。

这避免了直接全局抽帧时长episode获得更多概率的问题。全局draw序列再按rank分片；draw带有独立增强seed，保存任务映射指纹、epoch和游标，以便重启与多worker预取时重放。

## 续训与学习率

| 阶段 | 学习率与策略 | 资源与global batch |
| --- | --- | --- |
| 初始→5k | `1e-4 → 5e-5` | 4卡，8×5×4=160 |
| 5k→10k | `5e-5 → 2.5e-5`，余弦 | 4卡，20×2×4=160 |
| 10k→15k | `2.5e-5 → 1.25e-5` | 后续迁移到2卡，保持global batch160 |
| 15k→15.2k | 200步从`1.25e-5`升至`7.5e-5` | 2卡，20×4×2=160 |
| 15.2k→25k | 余弦下降至`2.5e-5` | FP32、dist_muon、梯度检查点 |

15k时开始新的任务采样阶段，归档旧数据游标；17k时更新为10/90增强配方。后续保存模型、优化器、rank状态、学习率调度、采样器以及Python/NumPy/CPU/CUDA RNG状态。

[training_hooks.py](../tools/continuation_15000/training_hooks.py)在恢复时核对实际学习率与训练阶段，在优化器更新前跨rank检查非有限loss/梯度。[gates.py](../tools/eval_after_training/gates.py)要求训练完成标记、正确退出码、完整分布式checkpoint和6个HF分片具备后，才允许评测启动。25k实际训练验证记录见[公开摘要](../experiments/benchmarks/step22000_step25000/summary.json)。

## 时序一致的10/90图像增强

实现位于[augmentation.py](../tools/continuation_17000/augmentation.py)。10%保留原图，90%进入随机组合分支。下列触发概率均是组合分支内的条件概率：

| 变换 | 概率 | 范围 |
| --- | ---: | --- |
| 光度与色温 | 80% | 亮度0.25–1.10，contrast0.5–1.5，饱和度0.4–1.6，红蓝增益±5% |
| 缩放 / 平移 | 50% | 缩放0.90–1.10，平移≤6%，露出边界补黑 |
| 矩形遮挡尝试 | 95% | 宽高各占4%–10%；无安全区域则跳过 |
| 高斯 / 椒盐噪声 | 50% / 15% | 高斯σ=1–3/255，椒盐比例0.1%–0.5% |
| 高斯 / 运动模糊 | 25% / 10% | 互斥，高斯3×3，运动核3或5 |
| JPEG | 30% | 质量35–90 |

同一draw的随机参数可重放；每个相机的当前/未来图像使用相应的一致空间变换，并把相同增强RGB交给策略、深度教师和视频教师。遮挡保护使用边缘、局部对比度和中央工作区的保守启发式，**不等同于语义分割**。

这些是像素观测变换；未引入生成模型编辑、替换真实场景物体或randomized训练样本。多项训练设置同时变化，现有结果不是逐项增强或采样策略的严格独立消融。

## 显存与速度取舍

4卡、micro batch20、累积2次的同checkpoint短测，排除前10步后：

| 梯度检查点 | 平均step时间 | 峰值显存 |
| --- | ---: | ---: |
| 开启 | 11.421s | 50.19GiB |
| 关闭 | 11.402s | 79.19GiB |

关闭仅提速约0.17%，增加约29GiB峰值占用，选择继续开启。[历史测量记录](../experiments/records/resume_5000_to10000_gc_compare_20261014_154104/gradient_checkpointing_decision.json)保留了测量口径。

后续2卡、micro batch20、累积4次并启用新增强的25k阶段，平均20.44s/step，峰值reserved memory74312MiB。GPU数量、增强及统计口径不同，不把该数值与4卡短测直接作速度提升比较。

## 闭环评测与场景修复

固定setting为clean+seen、randomized+unseen；FP32、固定执行50步，关闭录像。每个仿真进程配独立模型服务。共享模型并发方案曾做一致性探索，未满足严格复现门槛，正式结果继续使用独立进程。

记录环境seed、完整指令和推理seed。只接受50条连续episode、唯一有效seed、成功计数与最终汇总一致的完整任务结果。[汇总工具](../tools/eval_after_training/aggregate_scene_campaign.py)拒绝部分任务替换完整任务，并输出配对差值和不确定性。

`get_cluttered_table`原先用可变列表作为默认边界，并原地累加桌面偏移。`dump_bin_bigbin`、`put_bottles_dustbin`有非零偏移，多次初始化会改变后续杂物分布；跳过无效候选seed后，单靠同一个seed无法复现场景。

修复每次创建独立的边界列表；[scene_repair.py](../tools/eval_after_training/scene_repair.py)还保存专家有效场景的物体位姿和速度、机器人关节/驱动状态、场景配置及RNG，在新进程恢复并校验，避免重复物理沉降导致初始状态偏移。两个任务在GPU1生成参考、GPU2独立重放，均通过了真实场景短测。

25k的两项重测完成，修正randomized总分为43.52%。22k的剩余48项完成，两项补测后来因推理服务中断停止；状态在公开摘要中保留为partial，未补齐结果、未宣布综合胜出。

## 实时推理

项目采用的RTC方案将旧动作执行与新块生成重叠，并在Flow Matching生成过程中约束衔接区。它与训练采样、图像增强、固定块评测分别记录；现有分数不衡量RTC收益。时间对齐与梯度记号见[RTC说明](rtc.md)。
