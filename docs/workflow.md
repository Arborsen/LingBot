# 仓库维护与 VS Code 提交

commit/push 只提交所选文件，不会移动目录。保持目录有序靠统一的新文件位置和忽略规则；主仓库不要求安装 Git hooks，也不在提交时启动评测。

## 新内容放在哪里

| 新内容 | 位置 | 是否提交 |
| --- | --- | --- |
| 学到的原理、复现步骤、排错结论 | `docs/` | 是 |
| 通用工具 | `tools/` | 是 |
| 对模型或仿真代码的修改 | 对应源码目录 | 是，先确认目标仓库 |
| 实验配置与结果摘要 | `experiments/records/<实验名>/` | 是 |
| 原始配置、临时脚本副本、视频、日志、缓存 | `reproduce_artifacts/<实验名>/` | 新文件默认不提交 |
| 数据、下载模型与权重 | `datasets/`、`models/` 或实验运行目录 | 否 |

给新实验取稳定名称，例如 `20261014_clean_seen_baseline`。一次实验的代码版本、模型检查点、任务集合、seed、推理精度和归一化输入都应记录；手写说明可放在对应归档目录的 `notes.md`，汇总工具不会覆盖它。

既有实验目录和源码路径继续使用。历史实验中已跟踪的文件不会因为 `.gitignore` 改动而退出 Git，修改它们仍会出现在待提交列表。忽略规则主要拦住后续新生成的运行产物；这不是对全部已跟踪文件的提交拦截。

## 每次实验后的流程

1. 在 `reproduce_artifacts/<实验名>/` 保存 `run_config.json`，沿用现有配置字段。运行结果使用 `progress.json` 和结束时的 `results.json`。
2. 从主仓库根目录执行 `python tools/archive_experiments.py`。
3. 检查 `experiments/README.md` 的完成状态和统计口径，补充实验目录的 `notes.md`。
4. 在 VS Code 源代码管理中选择 **LingBot**，查看 diff，暂存本次需要提交的文档、工具、源码修改和实验摘要。
5. commit/push；下次继续使用同一套位置约定。

汇总只记录一次读取到的快照。运行中的实验会继续变化，需要再次执行命令才能更新归档。若某个 JSON 尚未写完或无法解析，命令会报错，此时等原始文件写完后重试。

手写实验也可以使用 `experiments/<实验名>/README.md` 和 `config.yaml`，不必为它改造评测器。自动索引只覆盖有 `run_config.json` 的旧格式运行目录。

## VS Code 中的多个 Git 仓库

本地的 `RoboTwin/` 和 `lingbot-vla-v2/` 内也有 Git 元数据，但主仓库当前保存的是普通源码文件快照，没有改成 submodule。GitHub 克隆主仓库不会自动获得它们内部的 Git 历史。

- 记录整个学习工作区时，在 **LingBot 主仓库**暂存和提交；根目录新增的文档与汇总工具属于这里。
- 准备模型侧上游 PR 时，在 **lingbot-vla-v2** fork 建分支并提交具体修复；其 `origin` 是个人 fork，`upstream` 是原项目。
- 本地 **RoboTwin** 的 `origin` 指向上游原仓库。准备 PR 时先使用个人 fork，确认推送目标。

在内部仓库提交不会自动替主仓库提交文件快照；在主仓库提交也不会替内部仓库生成提交。需要同时更新两边时，分别查看两边的 diff。此结构先服务当前比赛，后续确有独立维护需求再考虑 submodule。

## 持续维护

重复脚本先保留历史版本，新改动逐步收敛到所属源码目录或 `tools/`。优先把硬编码路径改成命令行参数或环境变量；不要把个人参数作为上游默认值。

贡献说明新增 PR 链接和状态，实验说明新增结论。CI 检查新工具和统计逻辑，不启动模型下载、GPU 训练或仿真评测。
